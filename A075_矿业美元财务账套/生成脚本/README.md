## 提速（opt）

用户原话：「帮我优化一下A075的这个模板，录入数据及保存时非常卡顿，接近死机了」。
规矩：**不改功能、不改任何报表结果**（同样的录入，所有账、表、凭证、报表每格结果一样），不改容量；Excel 2010 / WPS 能用
（不用 FILTER / XLOOKUP / MAXIFS / TEXTJOIN / IFS / LET / 动态数组、INDIRECT、TODAY / NOW；OFFSET 只在下拉名称里）。

### 病根

原来录任何一格，LibreOffice / Excel 要重算 37～40 万个公式（静态扇出，见下），而且其中几千个各自把 1.8 万行【记账分录】整列翻一遍：
科目余额表按 `$A7&"*"` 模糊 SUMIFS、明细账 SMALL＋MATCH、记账分录 / _凭证索引用 `INDEX(整列,第几笔)` 取流水（一格变、整列的公式都脏）、
现金流水总表余额和合并分组 O(n²)、往来余额表 / 月末结转 / 经营报表按日期＋科目开头整列扫。录一格≈整本重算一遍。

## WPS 存盘修正（wps，10/14 下午）

### 为什么

用户用 WPS 12.1。WPS 存 xlsx 的规矩（从 8 本用户用 WPS 存回的文件归纳，证据在 A074 评审 `review_perf_gain.md` §1.2）：
同一列往下拖的公式（共享公式），只要直接写了「别的表!格子」或往下撑的区域（`$A$5:A5`、`A$5:A5`），WPS 就拆成一格一条全文写进文件；
只用名称（名称指向别的表也行）、只引用本表的照样共享。A075 原件就是这样被存成 85.8 MB XML / 8.2 MB 文件的（我们发过去的 956 组跨表共享公式全被拆开）。
提速版（opt）把取流水改成「直接引用第 k 行」，又加了 14.4 万格 `INDEX(记账分录!…)` 的 _分录精简，按这个规矩估：XML 66.5 MB，WPS 存一次 131.6 MB。
