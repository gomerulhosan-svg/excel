# A075 · 矿业美元财务账套（提速版）

> 你的要求：**「帮我优化一下A075的这个模板，录入数据及保存时非常卡顿，接近死机了」**

成品：`A075_矿业美元财务账套（提速版）.xlsx`。这是空模板，基础资料、科目表、记账规则、汇率都取自你 10/14 上传的那本，流水 0 行。
你上传的原件原样存在 `参考/A075_用户上传原件-2026.10.14.xlsx`。

## 一句话

**怎么录、录在哪、出什么账和报表，都没变。** 同样的数录进去，所有账、表、凭证、报表的结果每一格都跟原来一样。
改的只是后台公式的写法，分两件事：

1. **存盘卡。** 原因是 WPS 存盘时有个规矩：同一列往下拖的公式，只要写了「别的表!格子」或者 `$A$5:A5` 这种往下撑的区域，
   就不再按「同一列只记一次」存，而是一格一条全文写进文件。你那本就是这样被存胖的：解压后 85 MB，文件 8.2 MB。
   现在这两类写法全部换掉了，同一列的公式 WPS 存盘时只记一次。按 WPS 的规矩估算，存一次以后还是约 60 MB，不会再胖。
2. **录入卡。** 原来录一格，表里约 40 万个公式要重算，其中几千个各自把 1.8 万行分录从头翻到尾，等于录一格就整本重算一遍。
   现在这些公式只看有数的那几行，或者只看相关的那一段。

## 快了多少（LibreOffice 实测）

下面是 LibreOffice 关掉多线程后实测的秒数，算的是录一格之后要等多久，包括「通知相关公式要重算」和「重算」两段。
测法是从空表开始录，先填好对应科目、报表月和汇率，再录 20 笔流水和几张业务单。

「原来」那一列是你上传的那本，今天同一套测法测 3 次取中位数。「现在」只测了 1 次。
WPS 和 Excel 的算法跟 LibreOffice 不一样，还会用多核，秒数会不同，但快慢的比例大致可以参考。

| 录哪一格 | 原来 | 现在 |
|---|---|---|
| 流水：日期 | 103～105 秒 | 12 秒 |
| 流水：账户 / 类别 / 金额 | 96～106 秒 | 15～16.5 秒 |
| 流水：摘要、备注 | 0.1 秒 | 0.02 秒 |
| 采购入库：单价 | 101 秒 | 14 秒 |
| 领用出库：数量 | 96 秒 | 12 秒 |
| 销售结算 / 工资计提 / 手工凭证 | 95～99 秒 | 8～9 秒 |
| 录一整笔流水（日期、账户、类别、金额、摘要合计） | 约 400 秒 | 约 60 秒 |
| 录了约 300 笔流水和各业务表以后，改一格流水金额 | 112 秒 | 26 秒 |
| 打开文件 | 107 秒 | 24 秒 |
| 文件大小（空表） | 8.2 MB（解压后 85 MB） | 4.9 MB（解压后 60 MB） |
| WPS 存一次以后，解压后多大（按 WPS 规矩估算） | 85 MB | 60 MB |

- 录一笔流水快了约 7 倍，业务单快了 7～12 倍。
- 存盘那一行没法在这里用 WPS 实测。LibreOffice 存盘不分公式写法，现在跟原来差不多，约 20 秒。
  WPS 存盘要写的东西跟文件解压后的大小成正比，现在比你那本少约三成。
- 要是你开着「手动计算」，存盘前 WPS 会先整本重算一遍。这一步在 LibreOffice 里，一年数据的那套原来约 100 秒，现在约 13 秒，存盘会明显快很多。

**请你在 WPS 里试两件事，各花 1 分钟：**

1. 录一格流水金额，看要转圈几秒。
2. 存一次盘，看文件有多大。正常应该在 5 MB 左右；超过 6 MB 就告诉我们。

## 改了哪些地方

都在隐藏列、隐藏表或名称里，你看到的格子没动。

1. **取数改用「分段名称」。** 记账分录、凭证索引要取流水第几笔时，不再直接写「现金流水总表!AG606」，改成从 100 行一段的名称里取。
   一共约 1,900 个名称，都是隐藏的，名称管理器里看不到。这样 WPS 存盘不拆公式，录一格也只牵动那一段。
2. **「从第一行到本行」的累计改成两段相加。** 账户余额、按天合并凭证、凭证号这些公式，原来写成 `$A$5:A5` 这种往下撑的区域。
   现在改成「前面各段」加「本段到本行」，算出来的数一样，WPS 存盘不拆。
3. **算法换成精确查找。** 科目余额表、明细账、月末结转、往来余额表、经营报表，原来按「科目编码开头是 1002 的」这类条件把 1.8 万行分录整列模糊查，
   现在分录里先算好「科目第几行×月份」这种数字键，按键精确汇总；明细账每行只精确找一次。
4. **只看有关的那几行。**
   - 账户余额按 100 行一块累计，不再每行把上面所有行加一遍；
   - 各种合计只算到有数的最后一行。
   - 「最后一行」只看日期、账户、类别、收入、支出五列，所以录摘要、备注、项目、往来不会牵动整张表，瞬间完成。

对你看得到的结果，跟原来有三处不一样：

- 【资金账户余额表】K 列：「对应科目」空着的账户，原来显示 #VALUE!，现在显示空或 0；K25 合计行现在按其余账户算出合计。
- 【数据校验】多了第 41 项，就是上面说的插删行检查。首页的「数据校验」汇总也把它算进去了。
- **手工凭证金额请保留两位小数。** 填了三位小数（比如 100.005）时，上级科目、科目余额表合计行、资产负债表未分配利润和合计会比明细多 0.01。两位小数时跟原来一样。
